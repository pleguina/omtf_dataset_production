## 2. Current Workflow Reconstruction

### Step 1 — CMSSW setup

| Item | Value |
|---|---|
| Script | `scripts/setup_cmssw.sh` |
| Command | `bash scripts/setup_cmssw.sh` |
| CWD | `~/omtf_hecin_dataset_production` |
| Environment | plain bash on lxplus, no cmsenv yet |
| Input | CMSSW version string hardcoded inside the script |
| Output | `~/CMSSW_14_2_0_pre2/src/` with fragments copied in; EMTFTools/ParticleGuns compiled |
| Hidden assumptions | EMTFTools source is fetched from a **colleague's AFS path** (`/afs/cern.ch/user/c/cvicovil/public/forPelayo/emtftoolsparticleguns`). If that user removes or moves the directory, setup breaks silently. |
| Failure mode | `cp` fails on the EMTFTools tree → `scram build` fails → all configs that use `FlatRandomPtGunProducer2` are unusable. |

### Step 2 — CMSSW config generation

| Item | Value |
|---|---|
| Script | `scripts/generate_configs.sh` |
| Command | `bash scripts/generate_configs.sh` (must run inside cmsenv) |
| CWD | `~/omtf_hecin_dataset_production/configs/` |
| Environment | `scramv1 runtime -sh` (sourced at the top of the script) |
| Input | `fragments/*.py` (physics), geometry/GT/era/beamspot hardcoded in the script |

| Failure mode | Adding a new dataset requires editing the script body, not a config file. Changing the geometry/GT requires editing in multiple places. |

### Step 6 — Condor job execution (on worker node)

| Item | Value |
|---|---|
| Script | `condor/run_job.sh <DATASET> <PROCID> <SKIPEVENTS> <NEVENTS>` |
| Environment | worker node, /cvmfs mounted, cmsenv set up inside the script |
| Input | `configs/${DATASET}_cfg.py` + `customize_omtf_dumper.py` (copied to scratch) |
| Patching | Python heredoc patches `maxEvents`, random seed, and output filenames via environment variables |

| Seed formula | `PROCID × 7919 + 13` (deterministic per-job but never stored in any registry) |
| Hidden assumptions | `CMSSW_DIR` is derived from `${USER}` → `/afs/cern.ch/user/${USER:0:1}/${USER}/CMSSW_14_2_0_pre2`. Another user on the same Condor pool cannot use a different CMSSW checkout. |

## 4. Target Architecture

The mental model for a campaign:

```
Campaign YAML
  ├── name, owner, description, version
  ├── physics block         ← currently scattered across fragments/*.py
  ├── cmssw_profile         ← currently hardcoded in 5 scripts
  ├── production block      ← currently in create_condor_subs.sh BASH array
  ├── storage block         ← currently hardcoded in run_job.sh
  ├── condor_profile        ← currently in individual .sub files
  ├── data_contract         ← currently hardcoded in make_graphs.py
  └── validation rules      ← currently absent
```

### Key constraints from this repository

1. **Fragment files stay as CMSSW Python.** They contain `cms.EDProducer` objects that `cmsRun` must import. The campaign YAML references the fragment file name; it does not duplicate the physics parameters.
2. **`cmsDriver` stays.** Configs should continue to be generated by `cmsDriver`. The campaign runner wraps the call.
3. **`customize_omtf_dumper.py` stays.** It is a stable CMSSW customiser copied to the worker node scratch directory at runtime.
4. **Condor `.sub` files become rendered templates.** One Jinja2 template replaces 50+ hand-written `.sub` files.
5. **A campaign registry JSON file** records cluster IDs, expected file counts, and validation status alongside the campaign YAML.

## 6. CMSSW Profiles

A profile describes one CMSSW checkout and its setup commands. Multiple users or releases each get their own profile file.

```yaml
# profiles/pleguina_cmssw14.yaml
name: pleguina_cmssw14
cmssw_base: /afs/cern.ch/user/p/pleguina/CMSSW_14_2_0_pre2
scram_arch: el9_amd64_gcc12
setup_script: /cvmfs/cms.cern.ch/cmsset_default.sh
```

```yaml
# profiles/other_user_cmssw14.yaml
name: other_user_cmssw14
cmssw_base: /afs/cern.ch/user/x/xuser/CMSSW_14_2_0_pre2
scram_arch: el9_amd64_gcc12
setup_script: /cvmfs/cms.cern.ch/cmsset_default.sh
```

The generated `run_job.sh` sources a rendered setup snippet instead of hardcoding the path:

```bash
# --- Rendered at submit time from profiles/pleguina_cmssw14.yaml ---
```

## 7. Data Contracts

Two trees coexist in the same ROOT file. This split must be explicit:

| Tree | Used by | Purpose |
|---|---|---|
| `simOmtfPhase2Digis/OMTFAllInputTree` | `make_graphs.py` | Full-region stubs with per-stub SimTrack truth → GNN training input |
| `simOmtfPhase2Digis/OMTFHitsTree` | `check_ntuple.py`, `validate_production.py` | Candidate-matched stubs → efficiency / fake-rate studies |

```yaml
# contracts/omtf_allinput_v1.yaml
name: omtf_allinput_v1
hits_tree: simOmtfPhase2Digis/OMTFAllInputTree
candidates_tree: simOmtfPhase2Digis/OMTFHitsTree
nano_tree: Events

# internal_name -> ROOT branch name
fields:
  event_num:    reg_eventNum
  processor:    reg_iProcessor
  stub_layer:   reg_stub_layer
  stub_phi_hw:  reg_stub_phiHw
  stub_phiB_hw: reg_stub_phiBHw
  stub_eta_hw:  reg_stub_etaHw
  stub_quality: reg_stub_quality
  stub_bx:      reg_stub_bx
  stub_r_cm:    reg_stub_rHw
  track_id:     reg_stub_trackId

```

If another user's OMTF dumper uses different branch names, they provide a different contract file. The graph converter and validators read branch names from the contract — zero code changes.

## 8. Plugin System

With one dataset type in the current repository, a minimal two-file plugin is sufficient:

```
plugins/
├── omtf_allinput/
│   ├── contract.yaml          (same as contracts/omtf_allinput_v1.yaml)
│   ├── validate.py            (file-level + branch + event + graph shard checks)
│   └── convert_to_graph.py    (current make_graphs.py logic extracted as a function)
└── omtf_das_reemul/
    ├── contract.yaml
    ├── validate.py
    └── convert_to_graph.py
```

Suggested abstract interface (Python):

```python
from abc import ABC, abstractmethod
from pathlib import Path

class DatasetPlugin(ABC):

    @abstractmethod
    def validate_root_files(self, root_files: list[Path], contract: dict) -> dict:
        """Return a report dict: {ok: bool, details: [...]}."""

    @abstractmethod
    def convert_to_training_dataset(
        self,
        root_files: list[Path],
        contract: dict,
        output_dir: Path,
    ) -> dict:
        """Convert ROOT files to .pt shards. Return provenance dict."""

    @abstractmethod
    def make_validation_report(self, dataset_dir: Path) -> dict:
        """Validate .pt shards. Return {ok: bool, metrics: {...}}."""
```

For now only `omtf_allinput` is needed. The interface exists so a second user can add a plugin without touching the campaign runner.

## 10. Validation Layer

### What exists today

| Check | Tool | Tree checked | Status |
|---|---|---|---|
| cmsRun completes | `run_smoke_tests.sh` | — | ✅ |
| Tree exists + has entries | `run_smoke_tests.sh` | OMTFAllInputTree, OMTFHitsTree | ✅ |
| Branch presence | `check_ntuple.py` | OMTFHitsTree | ✅ |
| File exists + non-zombie | `check_signal_eos.py` | OMTFHitsTree | ⚠️ S1–S5 only |
| Physics QA (hits, eff, charge) | `validate_production.py` | OMTFHitsTree | ✅ but wrong tree for GNN |
| OMTFAllInputTree branch check | — | **nothing** | ❌ |
| NaN/Inf in node features | — | **nothing** | ❌ |
| Graph shard shape consistency | — | **nothing** | ❌ |
| Label sanity (track_id) | — | **nothing** | ❌ |
| Graph-build smoke test on `.pt` | — | **nothing** | ❌ |

### Proposed checks by stage

**Stage A — After Condor jobs finish (file-level)**

- Count output files vs expected from registry
- Open each file with `uproot.open()` — zombie / corrupt detection
- Check `OMTFAllInputTree` exists and has entries > threshold
- Check all required branches present (from contract YAML)
- Check no branch is entirely zero (catches missing truth labels)

**Stage B — Physics coverage (event-level)**

- Non-zero `track_id` fraction ≥ threshold (signal label sanity)
- Empty-region fraction (regions with 0 stubs) below threshold
- `stub_phi_hw` distribution not clipped at extremes
- Optionally: gen pt / dxy coverage via NanoAOD tree

**Stage C — Graph shards (`.pt` level)**

- All `.pt` files loadable with `torch.load()`
- No NaN / Inf in `x_cont` or `edge_attr_cont`
- `edge_index` bounds valid: `max(edge_index) < num_nodes`
- `track_id.shape[0]` equals `x_cont.shape[0]`
- `edge_y.shape[0]` equals `edge_index.shape[1]`
- Fraction of graphs with `n_true_tracks == 0` below threshold
- Mean number of nodes within expected range (3–18 for OMTF overlap)

## 12. CLI Design (`forge`)

The tool is named `forge` — agnostic to any specific physics system or computing backend.

```bash
# Generate cmsDriver config + Condor .sub from a campaign YAML (no submission)
forge render campaigns/S2_displaced_v1.yaml

# Submit to Condor; writes cluster ID + metadata to registry.json
forge submit campaigns/S2_displaced_v1.yaml [--profile pleguina_cmssw14] [--dry-run]

# Show live status: condor_q + EOS file count + registry info
forge status S2_displaced_v1

# Live watch; refreshes every 30 s
forge watch S2_displaced_v1

# List held and failed jobs
forge failures S2_displaced_v1

# Generate a resubmit .sub for missing or bad files
forge resubmit-failed S2_displaced_v1

# Update registry with current EOS file count (no Condor needed)
forge collect S2_displaced_v1

# Run all validation checks (file + physics + graph shard)
forge validate S2_displaced_v1

# Convert ROOT files to .pt graph shards
forge convert S2_displaced_v1

# Print campaign summary from registry
forge report S2_displaced_v1

# List all known campaigns
forge list
```

**Framework recommendation:**

- Use `typer` if available in `venv_cmssw_root/` — clean API, auto-generates `--help`.
- Fall back to `argparse` if `typer` is not installed — zero new dependencies.
- Use `rich` for the status table if available, plain text otherwise.

## 15. First Code Patch

The single highest-value first patch is **Phase 2: `forge submit`** — a 80-line Python script that calls `condor_submit` and permanently records the cluster ID. It is purely additive and carries zero risk to the existing workflow.

```python
#!/usr/bin/env python3
# campaigns/submit.py — wrap condor_submit and record the cluster ID
"""
Replaces bare:
    condor_submit condor/G3.sub

With:
    python3 campaigns/submit.py condor/G3.sub --campaign G3_singleDisplacedOverlap_v1

Records the cluster ID, expected job count, EOS path, and git commit to
campaigns/registry.json so they are never lost again.
"""
import argparse
import json
import subprocess
import hashlib
import re
from datetime import datetime, timezone
from pathlib import Path

REGISTRY = Path(__file__).parent / "registry.json"


def load_registry() -> dict:
    if REGISTRY.exists():
        return json.loads(REGISTRY.read_text())
    return {}


def save_registry(reg: dict) -> None:
    REGISTRY.parent.mkdir(parents=True, exist_ok=True)
    REGISTRY.write_text(json.dumps(reg, indent=2))


def sha256_file(path: Path) -> str:
    return hashlib.sha256(path.read_bytes()).hexdigest()[:12]


def git_commit() -> str:
    try:
        result = subprocess.run(
            ["git", "rev-parse", "--short", "HEAD"],
            capture_output=True, text=True,
            cwd=Path(__file__).parent.parent,
        )
        return result.stdout.strip() if result.returncode == 0 else "unknown"
    except FileNotFoundError:
        return "unknown"


def condor_submit(sub_file: Path) -> int:
    """Run condor_submit and return the cluster ID."""
    result = subprocess.run(
        ["condor_submit", str(sub_file)],
        capture_output=True, text=True,
    )
    print(result.stdout)
    if result.returncode != 0:
        print(result.stderr)
        raise RuntimeError(f"condor_submit exited {result.returncode}")
    m = re.search(r"submitted to cluster (\d+)", result.stdout)
    if not m:
        raise RuntimeError("Could not parse cluster ID from condor_submit output")
    return int(m.group(1))


def count_jobs(sub_file: Path) -> int:
    """Count 'queue N' directives in a .sub file."""
    total = 0
    for line in sub_file.read_text().splitlines():
        stripped = line.strip().lower()
        if stripped.startswith("queue"):
            parts = stripped.split()
            total += int(parts[1]) if len(parts) > 1 and parts[1].isdigit() else 1
    return total


def extract_eos_path(sub_file: Path) -> str | None:
    """Try to find the output EOS path from a .sub file."""
    for line in sub_file.read_text().splitlines():
        if line.strip().lower().startswith("output") and "/eos/" in line:
            # output = /eos/user/.../logs/X_$(ProcId).out  →  /eos/user/.../logs
            path = line.split("=", 1)[-1].strip()
            return str(Path(path).parent)
    return None


def main() -> None:
    parser = argparse.ArgumentParser(
        description="Submit Condor jobs and record the cluster ID in campaigns/registry.json"
    )
    parser.add_argument("sub_file", type=Path, help="Path to the .sub file")
    parser.add_argument(
        "--campaign", required=True,
        help="Campaign name (e.g. G3_singleDisplacedOverlap_v1)"
    )
    parser.add_argument(
        "--eos-path", default=None,
        help="EOS output path (auto-detected from .sub if omitted)"
    )
    parser.add_argument(
        "--dry-run", action="store_true",
        help="Print what would happen without actually submitting"
    )
    args = parser.parse_args()

    sub_file = args.sub_file.resolve()
    if not sub_file.exists():
        raise SystemExit(f"ERROR: {sub_file} not found")

    njobs = count_jobs(sub_file)
    eos_path = args.eos_path or extract_eos_path(sub_file)

    if args.dry_run:
        print(f"[dry-run] Would submit {njobs} job(s) for campaign '{args.campaign}'")
        print(f"[dry-run] Sub file:  {sub_file}")
        print(f"[dry-run] EOS path:  {eos_path or '(not detected)'}")
        return

    cluster_id = condor_submit(sub_file)

    reg = load_registry()
    reg[args.campaign] = {
        "campaign_id": args.campaign,
        "owner": __import__("os").environ.get("USER", "unknown"),
        "submitted_at": datetime.now(timezone.utc).isoformat(),
        "sub_file": str(sub_file),
        "sub_file_sha256": sha256_file(sub_file),
        "repo_git_commit": git_commit(),
        "condor": {
            "cluster_id": cluster_id,
            "njobs_expected": njobs,
            "njobs_completed": None,
            "njobs_failed": None,
            "njobs_held": None,
        },
        "output": {
            "eos_path": eos_path,
            "files_found": None,
            "files_readable": None,
            "last_checked": None,
        },
        "validation": {"status": "pending", "run_at": None, "report_path": None},
        "graph_conversion": {"status": "not_started", "output_dir": None, "n_shards": None},
    }
    save_registry(reg)

    print(f"\n[forge] Recorded cluster {cluster_id} for campaign '{args.campaign}'")
    print(f"[forge] Registry: {REGISTRY}")
    print(f"\nNext steps:")
    print(f"  condor_q {cluster_id}                        # check live jobs")
    print(f"  condor_q -constraint 'ClusterId == {cluster_id}'  # filter by cluster")
    print(f"  python3 campaigns/submit.py --help           # see all options")


if __name__ == "__main__":
    main()
```

**Usage:**

```bash
# Old way (cluster ID lost):

# New way (cluster ID recorded in campaigns/registry.json):
python3 campaigns/submit.py condor/G3.sub --campaign G3_singleDisplacedOverlap_v1

# Dry run to check without submitting:
python3 campaigns/submit.py condor/G3.sub --campaign G3_v1 --dry-run
```

`campaigns/registry.json` accumulates one entry per campaign, is human-readable, diff-friendly, and can be committed to git.
