# prodv3 datasets

State: 2026-10-19. Location: `/eos/user/p/pleguina/omtf_hecin_datasets/prodv3/<dataset>/`.
Each dataset directory holds, per job `N`, two files:

- `omtf_hits_<dataset>_<N>.root`: TFileService output with the `simOmtfPhase2Digis/OMTFHitsTree` hit-level tree (OMTF emulator dumper v5.2, schema 3).
- `omtf_nano_<dataset>_<N>.root`: NanoAOD-style `Events` tree with the tables `omtfC`, `omtfU`, `omtfCNN`, `omtfUNN`, `gmtFwd`, `gmtFwdDisp`, `gmtSA`, `gmtSADisp`, `kmtfDisp` and the generator-muon truth.

There are 21 datasets, 8 394 hits files at the time of writing (79 GB). The B4 and PU200 jobs finish within hours; counts below are the jobs submitted.

## 1. How every sample is produced

Everything is generated from scratch (no input dataset): `EmptySource` -> particle gun fragment -> GEN, SIM, DIGI, L1 emulation -> dumpers.

| Item | Value |
|---|---|
| Release | `CMSSW_20_0_0_patch2` (`el9_amd64_gcc13`) + `pleguina/cmssw:wp8-dumper` (new OMTF, dumper v5.2) |
| Geometry / era | `ExtendedRun4D127` / `Phase2C26I13M9` |
| Global tag | `200X_mcRun4_realistic_v1` |
| Beamspot | `HLLHC14TeV`, `VtxSmearedHLLHC14TeV` |
| cmsDriver steps | `GEN,SIM,DIGI:pdigi_valid,L1` (`--customise_commands process.trackerGeometry.applyAlignment=cms.bool(False)`) |
| Pileup (`*_PU200`, `B4`) | `--pileup AVE_200_BX_25ns`, mean 200, 25 ns spacing; MinBias `Phase2Fall26GS` (`/MinBias_TuneCP5_14TeV-pythia8/Phase2Fall26GS-minbias_200X_mcRun4_realistic_v1-v1/GEN-SIM`), a fixed 3 000-file subset (every 6th file of the 18 175 at `T2_CH_CERN`): `configs_prodv3/pu_filelist_Phase2Fall26GS_MinBias.txt`. For `B4` the file list is rotated by the global job index. |
| No-PU samples | `mixNoPU` |
| Dumper | `configs_prodv3/customize_omtf_dumper.py` appended to every config (OMTF `DataROOTDumper2`, NanoAOD tables, schema metadata, producer commit) |
| Threads | forced to 1 thread / 1 stream per job |
| Event identity | `run = 3100` (campaign id), `lumi = jobId + 1`, `firstEvent = jobId * nEvents + 1`: (run, lumi, event) is unique across the campaign |
| Seeds | deterministic per (campaign, dataset, partition, job, engine) via crc32, all RNG engines |
| Provenance | `producerGitCommit = cmssw:6ddeeabdbb21;prod:9bf85693ee5e+dirty` (the `+dirty` is the production repo's uncommitted edits at tarball time) |

Where it comes from:

- Generator fragments: `omtf_dataset_production/fragments/<dataset>.py`. These are the `Configuration/GenProduction/python/OMTF_HECIN/` fragments used by cmsDriver.
- cmsDriver configs: `omtf_dataset_production/configs_prodv3/<dataset>_cfg.py`, generated by `scripts/generate_configs_prodv3.sh` (replays the prodv2 cmsDriver command with the prodv3 geometry, era, GT and pileup).
- Job script: `condor/run_job_prodv3.sh` (patches events, seeds, event identity and output names into the config), submit files `condor/prodv3_*.sub` and job lists `condor/prodv3_*.txt` (`Dataset, JobId, NEvents`).
- Runtime: no-PU about 3.5 min per 50 events, PU200 about 30 min per 50 events, B4 about 72 min per 50 events.

Why D127 / Fall26 and not the earlier D110 / Spring24: `CMSSW_20_0_X` cannot read SimDataFormats written before 20_0, so the Spring24 pileup and RAW samples are unusable (see `~/test/PRODV3_STATUS.md`).

### Generators

- `FlatRandomPtGunProducer2` (single muon gun, `EMTFTools/ParticleGuns`): muon `PartID = -13` with `RandomCharge = True` (so both charges), `PtSpectrum = flatOneOverPt`, flat phi over 2pi, vertex from `flatD0`.
- `FlatRandomOneOverPtGunProducer`: used by B4 with `PartID = 14` (neutrino).
- `FlatRandomLLPGunProducer2`: used by D2 (H -> 2 LLP, each LLP -> mu+ mu-).
- `MCSingleParticleFilter` ("etaFilter"): applied after the gun on the muon pseudorapidity at the vertex. Events failing it are dropped, so the number of events per file is lower than the requested jobs x events (measured on 3 files per dataset, see below).

### Muon definitions used in the names

| Label | Meaning |
|---|---|
| prompt | `MinDxy = 0`, `MaxDxy = 0.05 cm`, `MaxLxy = 0.1 cm` (vertex within 1 mm), `VertexSpectrum = flatD0` |
| disp(laced) | `MinDxy = 0.2 cm`, `MaxDxy = 50 cm` (flat in d0), `MaxLxy = 200 cm` (vertex inside MB1) |
| overlap (prompt) | gun `|eta| < 1.24`; filter keeps `0.82 < |eta| < 1.24` at the vertex |
| overlap (displaced) | gun `|eta| < 1.4`; filter keeps `0.6 < |eta| < 1.4` at the vertex (displaced muons reach the overlap at station 2 from outside 0.82-1.24, so select on `GenMuon_etaSt2` in the analysis) |
| `pt<a>to<b>` | `MinPt = a`, `MaxPt = b` GeV, flat in 1/pT |

## 4. Other folders next to `prodv3/` (not in it)

- `prodv3_multibx/`: D2 with OMTF BX window [-1, 1]. `SAMuon` has no BX field, so the `omtf*`/`gmt*` NanoAOD tables mix BXs; use `OMTFHitsTree.omtfBx`.
- `prodv3_das/`: Fall26 DY (M10-50) and TT pilots re-emulated from DAS, no PU (`trueNumInteractions = 0`, also for the `_PU` named one): prompt physics control only, not a rate sample.
- `prodv3_smoke*`: smoke and test outputs, not for analysis.

## 5. Caveats for analysis

- Requested events per job are not the written events: the eta filters keep about 34-35% (prompt overlap), 47-49% (displaced overlap) and 83% (D2).
- Matcher ghosts: `CandidateSimMuonMatcher::ghostBust` removes cross-processor duplicate candidates before the dumper. `OMTFHitsTree` has them as rows flagged `matcherGhost`; for rates use NanoAOD `omtfC`/`omtfU`.
- `omtfCNN`/`omtfUNN` use the NN pT with weights `lutNN_omtfRegression_v435_FP.xml` (training provenance unknown); the baseline `omtfC`/`omtfU` uses the pattern pT.
- CSC slope is 0 with the official config (`runCCLUT_TMB=False` in Phase-2); the CCLUT variant was dropped.
- Prompt gun vertices: `MaxLxy = 0.1 cm`. Displaced guns are generated in 0.6 < |eta| < 1.4.
