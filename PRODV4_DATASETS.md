# prodv4 datasets (WP2 samples)

State: 2026-10-21. Location: `/eos/user/p/pleguina/omtf_hecin_datasets/prodv4/<dataset>/` (multi-BX LLP samples in `prodv4_multibx/<dataset>/`).
Each dataset directory holds, per job `N`, two files:

- `omtf_hits_<dataset>_<N>.root`: TFileService output with the `simOmtfPhase2Digis/OMTFHitsTree` hit-level tree (OMTF dumper, `producerSchemaVersion` 4).
- `omtf_nano_<dataset>_<N>.root`: NanoAOD-style `Events` tree with the tables `omtfC`, `omtfU`, `omtfCNN`, `omtfUNN`, `gmtFwd`, `gmtFwdDisp`, `gmtSA`, `gmtSADisp`, `kmtfDisp`, the generator-muon truth and the new LLP truth columns.

31 datasets, 17 804 of 17 826 jobs delivered (about 109 GB on EOS (94 GB in `prodv4/`, 15 GB in `prodv4_multibx/`), 22 jobs failed, see section 5). Jobs x events/job are the submitted values.

## 1. How every sample is produced

Everything is generated from scratch (no input dataset): `EmptySource` -> particle gun fragment -> GEN, SIM, DIGI, L1 emulation -> dumpers. Same chain as prodv3 (see `PRODV3_DATASETS.md`), with the changes below.

| Item | Value |
|---|---|
| Release | `CMSSW_20_0_0_patch2_prodv4` (`el9_amd64_gcc13`), branch `prodv4-truth` (commit `d2fbd05e033`), built from the prodv3 area |
| Geometry / era | `ExtendedRun4D127` / `Phase2C26I13M9` |
| Global tag | `200X_mcRun4_realistic_v1` (filled in the schema metadata) |
| Pileup (`*_PU200`, `B4`) | `AVE_200_BX_25ns`, MinBias `Phase2Fall26GS`; **new file subset**: every 6th file starting from the 4th (`configs_prodv4/pu_filelist_*`), disjoint from the prodv3 subset. B4 rotates the list by the global job index. |
| No-PU samples | `mixNoPU` |
| Threads | 1 thread / 1 stream per job |
| Event identity | `run = campaign*10000 + crc32(dataset) % 10000` (campaign 4000, multi-BX 4001; one run per dataset, no collisions among the 31), `lumi = jobId + 1`, `firstEvent = jobId*nEvents + 1`: (run, lumi, event) is unique across the campaign. prodv3 used the same run for every dataset. |
| Seeds | deterministic per (campaign, dataset, partition, job, engine), all RNG engines |
| Job script | `condor/run_job_prodv4.sh`; submit files `condor/prodv4_*.sub`, job lists `condor/prodv4_*.txt` (`Dataset, JobId, NEvents`) |
| Fragments | `fragments/<dataset>.py` (generated by `scripts/make_prodv4_fragments.py`; C13-C16 and B4 reuse existing fragments) |
| Configs | `configs_prodv4/<dataset>_cfg.py` from `scripts/generate_configs_prodv4.sh` |

### What is new in prodv4 (vs prodv3)

1. **LLP truth** (`FlatRandomLLPGunProducer2`, new product `llpTruth`): H and LLP mass/pT/eta/phi, drawn proper c*tau, decay vertex (x, y, z, c*t), the two daughter muons, decay bin, window and LLP index. H and LLP are not in HepMC (Geant4 would propagate them). NanoAOD columns in the generator-muon table: `GenMuon_llpIdx`, `llpBin`, `llpMass`, `llpPt`, `llpEta`, `llpPhi`, `llpBetaGamma`, `llpProperTime`, `llpDecayTime` [ns], `llpDecayLxy`, `llpDecayZ`, `llpDecayDist` [cm], `hMass`, `hPt`. Value -999 / -1 when absent (non-LLP samples). Two muons of one LLP share `llpIdx`.
2. **Decay bins** (`DecayBin` 0-3): decay position along the LLP flight direction relative to the overlap stations (barrel cylinders r = 4000 / 4900 / 5900 mm, endcap disks |z| = 6900 / 8300 / 9250 mm): 0 before station 1, 1 between 1 and 2, 2 between 2 and 3, 3 beyond. The flight distance is drawn from the exponential truncated to the bin, so each bin sample is conditional (not natural rates). Both LLPs of an event are in the bin. The station surfaces are approximate geometry values.
3. **Decay time**: Geant4 uses the gun's decay-vertex T (A/B test: first-hit TOF difference 29.40 ns vs truth decay time 29.41 ns), so SimHit times already contain the LLP flight delay (also true for prodv3 D2). `SimVertex/TpMuon_t = 0` is only a truth convention; `llpDecayTime` carries the decay time. Single-muon guns stay at t = 0.
4. **Stations with SimHit** (`TpMuon_` fields in `OMTFAllInputTree`): `nMuonSimHit`, `first/lastSimHitTof/Subdet/Station/Ring`, `min/maxStation{Dt,Csc,Rpc}WithSimHit` (signal-event muon hits matched by trackId+eventId; pileup TPs have none; a gap crossing leaves no SimHit).
5. **Schema metadata**: `OMTFSchemaMetadata` += geometry, era, globalTag, datasetName, campaignId.
6. Bit-for-bit check: on a gun sample (C4) all common branches of the nano (306), `OMTFHitsTree` and `OMTFAllInputTree` are identical to prodv3; only the new branches differ.

## 4. Caveats for analysis

- Requested events per job are not the written events (eta filters, see Ev/file).
- LLP samples are bin-conditional: the decay position is forced into the bin, so do not use the relative yields of bins as physics rates. Non-LLP samples have `GenMuon_llp*` = -999 / -1.
- `llpBin`/`llpDecayDist` are computed along the LLP direction with approximate station surfaces; a muon can still cross stations differently. Use `TpMuon_*StationWithSimHit` for what the muon really crossed.
- Matcher ghosts: use `OMTFHitsTree.matcherGhost` / NanoAOD `omtfC`, `omtfU` for rates; `omtfCNN`/`omtfUNN` use the NN pT with `lutNN_omtfRegression_v435_FP.xml` (provenance unknown).
- Seeds and event ids are disjoint from prodv3 (new run numbers, new pileup subset).
